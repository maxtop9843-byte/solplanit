# humanizer: 한국어 문구 자연스러움 검수

## 목적

원래 의미와 수치, 고유명사를 바꾸지 않으면서 한국어 화자가 실제 서비스에서 쓸 법한 문장으로 다듬는다.

## 특히 확인할 패턴

- 영어식 쉼표와 문장부호 과다
- 명사만 이어 붙인 딱딱한 문장
- `~에 대해`, `~을 통해`, `~할 수 있습니다` 같은 번역투 반복
- `되어진다`, `에 의해` 같은 불필요한 피동
- `중요한`, `효과적인`, `최적의`, `혁신적인` 같은 추상적·광고성 표현 남용
- 같은 길이와 구조가 반복되는 AI식 문장 리듬
- 주어·대명사를 한국어에서 필요 이상으로 반복하는 문장
- 세 가지 항목을 억지로 묶는 3박자 나열
- `~것입니다` 식의 단정형 결말 반복

## SolPlanit 적용 원칙

- 사용자가 묻는 질문을 사용자의 말로 쓴다.
- 전문 용어를 쉬운 말로 바꿀 수 있으면 바꾼다. 정확성을 해치면 기술 용어를 유지하고 바로 옆에서 설명한다.
- UI에서는 설명을 길게 늘리지 않는다. 짧고 자연스럽게 고치는 것이 우선이다.
- `태양광 설치 판단 솔루션` 같은 제품 소개 문구보다 `우리 집에 태양광을 설치하면 얼마나 아낄 수 있을까요?`처럼 실제 질문을 우선한다.
- `사용자 입력 기반 예상 발전량 분석 결과`처럼 명사가 겹치면 동사가 있는 문장으로 풀어 쓴다.
- 숫자, 날짜, 출처, 단위, 계산 결과는 절대 임의로 바꾸지 않는다.
- 직접 인용과 공식 명칭은 보존한다.

## 의미 보존 자체검증

최종 문구를 쓰기 전 다음을 확인한다.

- 수치·날짜·고유명사가 보존됐는가?
- 긍정/부정 의미가 뒤집히지 않았는가?
- 인과관계가 바뀌지 않았는가?
- 기술적 한계나 주의 문구가 약해지지 않았는가?
- 버튼의 실제 동작과 문구가 일치하는가?

## SolPlanit에서 좋은 문구의 기준

- 한 번 읽으면 무엇을 입력해야 하는지 안다.
- 결과가 무엇을 뜻하는지 전문지식 없이 이해한다.
- 과장하지 않는다.
- 영업 문구처럼 들리지 않는다.
- 번역체가 아니다.
- 설명 없이도 버튼의 다음 행동이 예상된다.
